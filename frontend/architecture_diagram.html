Inside the Paintbox

System Architecture

Three layers that talk to each other

🎨
Netlify
Static frontend — lives in frontend/ (HTML, CSS, JS, images, fonts).

Artworks are organised by series under frontend/artworks/. Chat widget in js/chat.js sends messages + a thread_id to Railway via POST /chat/v2. Thread ID lives in browser localStorage so conversations persist across visits.

Free hosting
🚂
Railway
Python FastAPI server, Docker deployed.

Runs the LangGraph agent + RAG pipeline. Stores conversation history via PostgreSQL (or in-memory fallback). User preferences saved in Postgres or JSON files. Commission requests are handed off to a link — no email is sent from the backend.

Docker deploy
🤖
Anthropic API
Hosts Claude Haiku 4.5.

Used for intent classification, ReAct tool-calling loop, preference extraction, RAG generation, and general chat. Commission questions get a static reply with no LLM call.

Pay-per-token
What happens when a visitor sends a message
1
Chat widget sends the message + thread_id to Railway via POST /chat/v2.
2
FastAPI calls chat_with_memory() → the compiled LangGraph graph is invoked.
3
Graph runs: loads preferences → classifies intent → routes to artwork / general / commission handler → extracts & saves preferences.
4
Artwork questions trigger the ReAct loop with ChromaDB lookups via Anthropic Claude Haiku. Commission questions get a static reply linking to the commissions page.
5
Final AI response is returned to the chat widget. The full trace appears in LangSmith.

ANTHROPIC_API_KEY — Claude API key  ·  POSTGRES_URI — PostgreSQL connection string for persistent memory (optional, falls back to in-memory)  ·  LANGCHAIN_TRACING_V2 LANGCHAIN_API_KEY LANGCHAIN_PROJECT — LangSmith observability

RAG Pipeline — inside react_node

1
Embed
The query is converted into a 384-dimensional vector using SentenceTransformer all-MiniLM-L6-v2. Runs locally on Railway — no API call, no cost.
→
2
Retrieve
Vector is queried against ChromaDB (local, persistent). Returns top 5 most semantically similar artwork documents. Results with distance above 1.5 are filtered out as low-confidence.
→
3
Generate
Anthropic Claude Haiku 4.5 receives retrieved context + conversation history. Two-step Chain-of-Thought: first reasons about intent, then generates a warm, gallery-guide-style answer.
What gets indexed into ChromaDB
On startup, document_loader.py scrapes every artwork page (frontend/artworks/**/*.html — recursively across all 9 series subdirectories), and the About page using BeautifulSoup. Each page becomes one document stored with title, series name, and URL as metadata.

Recursive scan: artworks are organised into series subdirectories inside frontend/artworks/ — portraits/, animal-portraits/, mythical/, thoughts/, camera-series/, diary-entries/, fanart/, cards/, misc/. The loader uses glob("**/*.html") to find them all. The backend passes "../frontend/" as website_path.
Series URL map (hardcoded in tools.py)
filter_by_series always returns the correct series page URL from a static SERIES_URLS dict — the LLM never guesses a URL. Covers all 8 series: Portraits, Animal Portraits, Mythical, Thoughts, Camera Series, Diary Entries, Fanart, Cards.

5 LangChain tools — backend/tools/ package, available to the ReAct loop

search_artworks(query) — tools/search_artworks.py
Semantic similarity search across the full ChromaDB collection. Embeds the query and returns up to 5 artworks with titles, series, descriptions, and URLs. Filters results above distance 1.5.
NOT used for specific titles or series names.
"Show me something dark and emotional" "Do you have anything about mythology?"
filter_by_series(series) — tools/filter_by_series.py
Lists all artworks in a specific series. Always returns the correct series page URL from the hardcoded SERIES_URLS map. Falls back to SERIES_ARTWORK_MAP if ChromaDB returns nothing.
Explicit docstring: do NOT call for individual artwork names.
"Show me all the Mythical artworks" "What's in the Diary Entries series?"
get_artwork_details(artwork_name) — tools/get_artwork_details.py
Looks up a specific artwork by title. Semantic search + exact title match preference.
Explicit docstring: do NOT use for series names — use filter_by_series instead.
"Tell me about Voices" "What is Icarus about?"
get_commission_info() — tools/commission_info.py
Returns static commission info — no arguments, no DB call. Includes contact links, commission types, and response time. Hardcoded in tools.py.
Note: the commission_intake node just replies with a link to the commissions page — it does not use this tool.
"How do I commission a piece?"
recommend_similar(artwork_name) — tools/recommend_similar.py
Two-step search: finds the source artwork's full document, embeds the entire content, then queries ChromaDB for thematically similar pieces. Returns up to 4 results excluding the source.
"I liked Icarus, show me more like it" "Recommend something like Trapped"
How the ReAct loop uses these tools
The LLM sees all 5 tool definitions in its context. Each iteration it outputs either a tool call (JSON with name + arguments) or a plain text response (the final answer). Tool calls are executed by LangGraph's built-in ToolNode, the result is appended as a ToolMessage, and the loop continues for up to 5 iterations. A complex question like "Tell me about Icarus and recommend something similar" triggers two tool calls in sequence.

Two-layer memory system

Layer 1 — PostgreSQL (or in-memory)
Managed by LangGraph's PostgresSaver if POSTGRES_URI is set; otherwise falls back to MemorySaver (resets on restart)
Stores the full message history — every HumanMessage and AIMessage per thread
Keyed by thread_id — a UUID generated in the browser, stored in localStorage
With Postgres: persists across server restarts and redeploys
Trimmed to last 10 messages before each LLM call to avoid token overload
Max 20 user turns per session, then visitor is asked to start fresh
Layer 2 — JSON files (user_prefs/)
One file per visitor: user_prefs/{thread_id}.json
Stores extracted interests — not raw messages
Updated after every exchange by extract_preferences
Loaded at session start by load_preferences, injected as system context
Commission requests are now submitted directly via the commissions page form — the chat agent no longer collects or files them
{
  "liked_series": ["Mythical", "Portraits"],
  "mentioned_artworks": ["Icarus", "Voices"],
  "tone": "curious"
}
Why two layers?
Postgres (or MemorySaver) holds the raw message log so the LLM can resolve follow-up references ("tell me more about it"). The preference store holds a distilled, high-level summary injected as system context — so even the very first message of a new session feels personalised. Only the last 10 messages are sent to the LLM to keep token usage low; the full history is preserved in the DB.

The old multi-turn intake (ask type → subject → occasion → style → timeline → contact, then db.save_commission() + Gmail SMTP notification) was removed in favor of a direct link to the standalone commissions page. The now-dead supporting code was deleted along with it: the COMMISSION_INTAKE_SYSTEM prompt, the _llm_commission LLM instance, the commission_data state field, and db.save_commission() / _send_commission_email() (including the unused commissions table creation and the now-unneeded GMAIL_USER / GMAIL_APP_PASSWORD env vars).

backend/app.py — FastAPI server & entry point
Railway runs this
What it does: Defines all HTTP endpoints and wires together every module at startup.

Key lines:

load_dotenv() — reads .env file locally; on Railway, env vars are injected directly.

@asynccontextmanager async def lifespan(app) — runs on startup: calls load_all_artworks() and index_documents() so ChromaDB is populated before the first request arrives. Runs on shutdown to log "shutting down".

Limiter(key_func=get_remote_address) — rate limiter keyed by visitor IP, enforced via the slowapi library.

app.add_middleware(CORSMiddleware, allow_origins=[...]) — whitelists Netlify and localhost so browsers don't block cross-origin requests to Railway.

MAX_MESSAGE_LENGTH = 500 — rejects messages longer than 500 characters to prevent abuse.

MAX_USER_TURNS = 20 — counts how many times the visitor (not the bot) has sent a message in this thread; soft-caps at 20 turns.

POST /chat/v2 — main chat endpoint. Validates the message → checks turn limit → calls chat_with_memory() → returns the AI response as JSON.

GET /chat/history/{thread_id} — returns the full conversation history for a thread (used on page load to restore chat).

DELETE /chat/history/{thread_id} — clears conversation (visitor starts fresh).

POST /reindex — re-scrapes all artwork HTML files and rebuilds ChromaDB without restarting the server.

GET /stats — returns how many documents are indexed in ChromaDB.

backend/rag.py — RAG pipeline (embed → retrieve → generate)
ChromaDB + Claude
What it does: Manages the vector database and the two-step AI generation used for artwork questions.

Module-level (runs once at import):
SentenceTransformer('all-MiniLM-L6-v2') — loads the embedding model into memory. Runs locally on Railway, free, converts text to 384-dimension vectors.
chromadb.PersistentClient(path="./chroma_db") — opens (or creates) the ChromaDB database on disk.
collection = chroma_client.get_or_create_collection("artworks") — the single collection storing all artwork documents.

Functions:

get_anthropic_client() — reads ANTHROPIC_API_KEY from env, returns an anthropic.Anthropic client. Raises if key is missing.

index_documents(documents) — clears the existing collection then re-adds every document. For each doc: calls embedding_model.encode(content) to get a vector, then collection.add() with the vector + metadata (title, series, URL).

search_similar(query, n_results=3) — embeds the query string, calls collection.query() to find the closest documents by cosine distance, returns a list of dicts with content + metadata + distance score.

generate_response(question, context_docs, conversation_history) — two-step Chain-of-Thought:
  Step 1 (Reasoning): sends the question + context + conversation history to Claude Haiku and asks it to reason about what the user wants (max 300 tokens).
  Step 2 (Response): sends the reasoning output + context to Claude Haiku to generate the final warm gallery-guide reply (max 250 tokens).
Documents with distance > 1.5 are filtered as low-confidence before either step.

build_search_query(question, conversation_history) — appends the last 2 user messages to the current question to help ChromaDB resolve follow-up references like "tell me more about it".

query_rag(question, conversation_history) — the public entry point: calls build_search_query → search_similar → generate_response.

get_collection_stats() — returns document count and collection name; used by the /health and /stats endpoints.

backend/db.py — Postgres persistence
Storage layer
What it does: Reads/writes visitor preferences. Falls back to JSON files when Postgres isn't configured.

_get_conn() — checks if POSTGRES_URI is set. If yes, opens a psycopg connection (reuses it if still alive). Returns None if no URI → triggers JSON fallback in every function.

setup_tables() — called on startup by app.py. Creates the user_prefs table if it doesn't exist (PostgreSQL CREATE TABLE IF NOT EXISTS).

load_user_prefs(thread_id, prefs_dir) — tries Postgres first (SELECT prefs FROM user_prefs WHERE thread_id = %s); falls back to reading prefs_dir/{thread_id}.json.

save_user_prefs(thread_id, prefs, prefs_dir) — upserts into Postgres (INSERT … ON CONFLICT DO UPDATE); falls back to writing the JSON file.

The old commission-saving + Gmail SMTP notification code (save_commission(), _send_commission_email(), the commissions table) was deleted — visitors now submit commissions via a form on the commissions page instead.

backend/document_loader.py — HTML scraper
Startup only
What it does: Scrapes all artwork HTML pages into plain-text documents that can be indexed into ChromaDB.

SERIES_ARTWORK_MAP — hardcoded dict mapping each series name to its list of HTML filenames. 8 series, 42 artworks total. Used by filter_by_series tool as fallback.

_ARTWORK_TO_SERIES — reverse lookup built at import time: filename → series name. Used by get_artwork_series().

clean_text(text) — strips extra whitespace and newlines with re.sub(r'\s+', ' ', text).

get_artwork_url(html_path, website_path) — turns a local file path like frontend/artworks/mythical/icarus.html into its public Netlify URL.

load_artwork_from_html(html_path, website_path) — opens an HTML file with BeautifulSoup, extracts: <h1> (title), <h6> (subtitle/dimensions), <p> tags (description), <h2> tags (section headings like "INSPIRATION"). Combines everything into a single content string that includes the URL so the chatbot can reference it.

load_all_artworks(website_path) — globs artworks/**/*.html recursively and pages/series/*.html, calls load_artwork_from_html on each file, returns a list of document dicts.

load_about_page(website_path) — loads pages/about.html specifically so the bot can answer questions about Ragini.

backend/agent/state.py — LangGraph state schema
Data shape
What it does: Defines the shape of the data that flows through every node in the graph.

messages: Annotated[list, add_messages] — the conversation history. add_messages is a LangGraph reducer: instead of replacing the list, each node's returned messages are appended to the existing list. This is what allows multi-turn memory.

intent: str — set by the classify node to "artwork", "general", or "commission". Read by the conditional edge to route to the right handler.

user_prefs: dict — loaded from Postgres/JSON at the start of each turn, updated by extract_preferences, saved back by save_preferences.

thread_id: str — the visitor's UUID, passed through state so nodes can use it without calling the checkpointer directly.

The old commission_data: dict field (used to track multi-turn commission intake progress) was removed — commission_intake now just returns a static link and needs no state.
📄
backend/agent/graph.py — LangGraph graph builder
Wiring
What it does: Creates and compiles the LangGraph graph once at import time. The compiled graph is a singleton reused for every request.

agent = PaintboxAgent() — instantiates all LLM clients and tool nodes. Happens once at startup.

graph.add_node(...) — registers all 7 nodes. Each node is a method on PaintboxAgent.

graph.add_conditional_edges("classify", agent.route_intent, {...}) — after classify runs, route_intent() reads the intent field from state and returns the name of the next node as a string.

postgres_uri = os.environ.get("POSTGRES_URI") — if this is set, uses PostgresSaver (persistent across restarts). If not, falls back to MemorySaver (in-memory, lost on restart). The try/except means a bad Postgres URI gracefully falls back instead of crashing.

compiled_graph = build_graph() — module-level call so the graph is compiled once when Python imports this file.
📄
backend/agent/nodes.py — all node implementations
Core logic
What it does: Every node in the graph is a method on PaintboxAgent. Each method takes state: AgentState and returns a dict of fields to update in state.

_make_llm(max_tokens) — factory that creates a ChatAnthropic instance with claude-haiku-4-5-20251001, temperature=0, and max_retries=3. Called once per token budget:
 · _llm_classifier — max 20 tokens (outputs one word)
 · _llm_main — max 1024 tokens (artwork answers, bound with tools)
 · _llm_chat — max 512 tokens (general chat)
 · _llm_extractor — max 512 tokens (outputs JSON)

The old _llm_commission instance was removed along with the multi-turn intake it powered.

_trim(messages, n=10) — slices the last 10 messages from state before sending to the LLM. Also skips forward past any orphaned ToolMessages so the LLM never receives a tool result without the preceding tool call.

load_preferences(state) — calls db.load_user_prefs() and returns {"user_prefs": prefs}. No LLM call.

classify(state) — sends just the last user message to _llm_classifier with a strict one-word system prompt.

react_node(state) — the artwork handler. Prepends GALLERY_SYSTEM + user preferences as system context. Loops up to 5 times: calls _llm_with_tools, if the response contains tool calls executes them via _tool_node and continues, otherwise breaks and returns all accumulated messages.

general_chat(state) — single LLM call with GENERAL_SYSTEM prompt. No tools.

commission_intake(state) — no LLM call, no state mutation. Returns a single fixed AIMessage pointing the visitor to the commissions page. The old multi-turn collector (asked type → subject → occasion → style → timeline → contact, then called db.save_commission()) was removed.

extract_preferences(state) — sends the last 4 messages to _llm_extractor, parses the JSON output. Merges with existing preferences (caps: 10 series, 20 artworks). Returns {} if JSON parsing fails.

save_preferences(state) — calls db.save_user_prefs(). No LLM call.
📄
backend/agent/prompts.py — all system prompts
LLM instructions
What it does: Defines the personality and rules for each LLM call as constants.

GALLERY_SYSTEM — the main artwork prompt. Three critical rules: (1) never name an artwork without a tool result, (2) always call a tool before answering, (3) say honestly if a tool returns nothing. Lists which tool to use for which type of question. Tone: warm, funny, conversational gallery guide.

CLASSIFY_SYSTEM — a strict one-word classifier. Outputs exactly commission, artwork, or general. No other output allowed.

GENERAL_SYSTEM — for small talk. 1–3 sentences, warm and brief, gently steers toward the art collection.

The old COMMISSION_INTAKE_SYSTEM prompt was deleted along with the multi-turn intake flow it drove.

EXTRACT_SYSTEM — instructs the LLM to output only a JSON object with liked_series, mentioned_artworks, and tone. Strict format prevents extra text that would break json.loads().
📄
backend/tools/base.py — shared constants for all tools
Shared config
What it does: Imports the ChromaDB collection and embedding model from rag.py so all tools share the same singletons without re-initialising them.

BASE_URL — the Netlify URL, used to build artwork and series page links.

CONFIDENCE_THRESHOLD = 1.5 — ChromaDB distance above which a result is considered too low-confidence to show. Used by search_artworks to filter out irrelevant results.

SERIES_URLS — hardcoded dict of series name → series page URL. This is the source of truth for series links; the LLM never guesses a URL.

COMMISSION_INFO — static text block about commissions, returned by the get_commission_info tool without any DB call.
📄
backend/tools/ — 5 LangChain tools
ReAct loop
Each tool is a BaseTool subclass with a name, description (what the LLM reads to decide when to call it), an args_schema (Pydantic model defining inputs), and a _run() method.

search_artworks.py — encodes the query with embedding_model.encode(), queries ChromaDB for top 5 results, filters out any with distance > 1.5, formats each as title + series + URL + 200-char snippet.

filter_by_series.py — case-insensitive match against SERIES_ARTWORK_MAP keys. Queries ChromaDB filtered by {"series": matched_series}. Falls back to the hardcoded filename list if ChromaDB has no indexed data yet. Always includes the series page URL from SERIES_URLS.

get_artwork_details.py — embeds the artwork name, queries ChromaDB for top 3, then picks the result whose title most closely matches the input string (exact substring match preferred over pure vector distance). Returns full content + series + URL.

commission_info.py — returns the static COMMISSION_INFO string from base.py. No arguments, no DB call. Used when a visitor asks general questions about commissioning; separate from commission_intake, which just replies with a link.

recommend_similar.py — two-step: first finds the source artwork's full document text using get_artwork_details logic, then embeds the full content (not just the title) and queries ChromaDB for the 5 most similar documents, excluding the source artwork itself. Returns up to 4 recommendations.
📄
backend/agent/__init__.py — public interface for the agent
Called by app.py
What it does: Exposes three clean functions to app.py so it never needs to import LangGraph internals directly.

chat_with_memory(message, thread_id) — wraps compiled_graph.invoke(). Passes the new HumanMessage and the thread config, then walks the returned messages in reverse to find the last AIMessage with content. Returns the fallback string "I'm sorry, I couldn't generate a response" only if no AIMessage is found.

get_conversation_history(thread_id) — calls compiled_graph.get_state(config) to read the checkpoint without invoking the graph. Filters the message list to return only HumanMessage and non-empty AIMessage entries as plain dicts with role and content.

clear_conversation(thread_id) — deletes the user_prefs/{thread_id}.json file. Note: the LangGraph checkpoint itself (in Postgres or memory) is not deleted here — only the extracted preferences file.
